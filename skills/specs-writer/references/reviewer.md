# Specs Reviewer

用于对已生成的 `design.md`、`plan.md`、`progress.md` 做独立、只读的语义评审。Reviewer 不修改文件，不提交代码，不替用户决定产品、安全或风险取舍。

## 输入

- 原始需求、已确认决定、非目标和验收边界。
- `design.md`、`plan.md`、`progress.md` 的路径。
- 项目规则、相关权威文档和必要的源码/测试入口。
- [contract.md](contract.md) 作为结构标准。

不要提供主 Agent 的完整讨论、预设答案或希望 Reviewer 赞同的提示。

## 评审维度

1. **需求对齐**：目标、非目标、可观察行为、契约和验收是否完整一致。
2. **架构与技术可行性**：职责归属、依赖方向、状态机、数据、权限和兼容是否成立。
3. **Task 边界**：Task 是否有明确产出和当前消费者；强相关 Task 是否应合并；拆分后是否产生重复读取或无意义交接。
4. **调度正确性**：不同端/代码域是否被共享契约或“同一功能”人为串行；硬依赖是否只用于消费实际实现产物；容量串行是否被误写成依赖；写集和资源是否冲突。
5. **上下文安全**：多 Task 是否一 Task 一 Worker/上下文；主 Agent 是否只做编排和验收；Worker 输入/回传是否足够有界。
6. **验证闭环**：Task 信号是否覆盖本 Task；Integration Gate 是否新增跨任务覆盖；Final Gate 是否统一收口；证据是否能证明状态。
7. **文档与产物边界**：design、调度表、Task/Gate 卡、Mermaid、progress 是否互相矛盾；临时过程契约是否位于 `work/contracts/` 且声明消费者和清理时机；正式测试是否在删除 `work/` 后仍可运行；长期 fixture 是否有 Task 写入范围，且没有擅自新增仓库级共享目录。
8. **Review 与人工边界**：Reviewer、主 Agent 和用户的责任是否分离；自动化结果是否被误写成人工验收。

只报告会改变需求正确性、实施质量、验证可信度或安全边界的问题。不要评审无关措辞和样式偏好。

## 严重级别

- `P1`：会阻塞实施，导致错误行为、契约矛盾、验证不可信或明显安全风险。
- `P2`：会显著增加返工或执行成本，或误导 Worker、造成资源冲突。
- `P3`：不阻塞当前执行的局部改进；默认不输出。

## 输出

```markdown
结论：PASS / CHANGES_REQUIRED / BLOCKED

### 阻塞项
- [P1] <问题>
  - 证据：<文件/章节/源码位置>
  - 影响：<为什么阻塞>
  - 建议：<最小修改>

### 应修项
- [P2] <问题>
  - 证据：
  - 影响：
  - 建议：

### 已核验
- <关键需求、依赖、路径或契约的简短结论>
```

存在 P1 时结论必须为 `BLOCKED`；存在 P2 时默认 `CHANGES_REQUIRED`；`PASS` 表示没有未解决的 P1/P2。Reviewer 输出到此结束，采纳、修改和复验由主 Agent 处理。
